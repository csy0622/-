## 一、总体架构

### 1.1 分层

```
             ┌──────────────┐
   H5 前端 ──▶│  Node 服务   │  ← Pi agent 底座（对话 / 工具循环 / 会话 / 压缩）
  (assistant/ │  (assistant/ │
   h5)        │   src)       │
             └──────┬───────┘
                    │ 工具层（TypeBox 签名）
     ┌──────────────┼──────────────────────┐
     ▼              ▼                      ▼
 Python 适配层   资讯 / 文章抓取        报告渲染
 (assistant/py)  (浏览器登录态 / HTTP)   (HTML, 白色系)
     │
     ▼
 icbt 内核（只读复用，不改）
 行情 / 面板 / 规则引擎 / 回测引擎 / 数据自检
```

原则：**Node 侧只做对话与编排，Python 侧只做数据与计算，渲染与展示分离。**

### 1.2 为什么不改 `icbt`

`icbt` 已跑通并验证过口径（无前视约束、四维数据自检、可复现 run_id）。助手只需要「调用」它：

- 只读复用 `icbt/runner.py`、`icbt/fetch.py`、`icbt/data.py`、`icbt/ops/checks.py`、`icbt/rules/*`；
- 在 `assistant/py/` 加一层薄 CLI，把已有函数包成「吃 JSON 吐 JSON」的进程接口；
- `icbt` 自身升级不影响助手，助手出问题也不污染回测平台。

### 1.3 与 Pi 上游的边界

| 目录 | 归属 | 说明 |
| --- | --- | --- |
| `packages/` | Pi 上游 | **一个字节都不改**，保持可跟上游 diff / 升级 |
| `assistant/` | 本项目 | 全部自有代码、配置、数据、文档 |

扩展 Pi 一律走它提供的扩展点（SDK 注入 / extension / 自定义工具），不改 `packages/`。

## 二、技术选型

### 2.1 Agent 运行时

用 `@earendil-works/pi-coding-agent` 的 **SDK**（而非从零用 `pi-agent-core`），因为需要会话管理、上下文压缩、资源加载与 hooks：

```ts
import { createAgentSession, DefaultResourceLoader, SessionManager } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession({
  resourceLoader: new DefaultResourceLoader({
    systemPromptOverride: INVESTMENT_SYSTEM_PROMPT,   // 投资助手人格与规则
  }),
  customTools: investmentTools,          // 见 3.1
  model,                                 // 见 2.2
});
```

保留 Pi 自带的 `bash` / `read` / `write`：本助手天然需要读写本地文件、以子进程调用 Python 适配层，这三个工具正好承载。

备选（如后期要换成独立服务进程）：用 `pi --mode rpc` 以 JSONL 驱动子进程（`docs/rpc.md` 里有 Python 客户端示例），或 `RpcClient`。

### 2.2 模型与 Provider

DeepSeek 是 Pi 的**内置 provider**，无需自己写适配：

| 项 | 值 |
| --- | --- |
| provider id | `deepseek` |
| baseUrl | `https://api.deepseek.com` |
| api | `openai-completions` |
| 密钥来源 | 环境变量 `DEEPSEEK_API_KEY`，或 `<agent-dir>/auth.json` |

零代码的替代方式是 `<agent-dir>/models.json` 里配一个 OpenAI 兼容块。密钥**只走环境变量或 `auth.json`**，不进仓库、不写进 `watchlist.yaml`。

**模型注册（2026-10-11 实测通过，结论与原假设不同）**：用你的 key 实测了你的 DeepSeek 账号，结果：

- 账号下实际可用的 id 只有两个：**`deepseek-flash`**（显示名 **DeepSeek-V4.1-Flash**，API 明确返回 `input_modalities: ['text','image']`）与 `deepseek-v4-pro`（纯文本）。
- **主模型 `deepseek-flash` 本身就支持图片** —— 已用日报截图实测，它能准确读出「贝塔」列表头与全部 10 个数值（`0.06、—、0.59、1.20、0.91、1.19、1.19、1.18、1.23、1.31`）以及 +19.0% 的偏离值。
- → **不需要单独注册视觉模型，复盘读图也不需要切模型。** 原先设想的 `deepseek-v4-flash-vision-exp` 在你这套账号下并不存在（那是 Pi catalog 里的实验性条目）。
- 注册方式（零代码）：在 `<agent-dir>/models.json` 声明 provider 与模型，密钥用 `$DEEPSEEK_API_KEY` 环境插值，**不落盘明文**。本项目放在 `assistant/pi-agent/models.json`，用 `PI_CODING_AGENT_DIR` 指向该目录。
- 实测命令：`PI_CODING_AGENT_DIR=…/assistant/pi-agent DEEPSEEK_API_KEY=… ./pi-test.sh --model deepseek/deepseek-flash --print "…"` —— 成功跑通，并完成了一次真实的 bash 工具调用（返回 `pi-tool-ok`）。

**取数坑（实现时必须处理）**：

- `stock_zh_index_hist_csindex` 返回的**首行是 base-date 合成行**（如 2004-01-01，收盘值与次行相同），直接 `min(date)` 会把起点误判成 2004 年——**必须丢弃首行**再用。
- 申万一级有 3 个行业不足 10 年，做板块长历史回测时要么剔除，要么改用中证对应行业指数。
- 国证指数（980032 新能源车电池）不在中证口径，`csindex` 接口取不到，需另找取数口径或改用申万「电力设备」。
- `index_hist_sw` 的 `symbol` 要用**裸代码**（`801010`），传 `sw_index_first_info()` 返回的 `801010.SI` 会报列名错误。
- 国证指数（`980032` 新能源车电池）**不在中证口径**：`csindex` / 东财都取不到，只有新浪 `stock_zh_index_daily(symbol="sz980032")` 可取。
- 东财**行情**接口（`fund_etf_hist_em`、`stock_zh_index_spot_em`）被**网络层立即重置**（0.1s 就断开——**不是限频**，限频会返回状态码；同日实测上午可用、下午起持续被拒）。→ 必须多源回退。
- **复权价的替代口径（2026-10-11 找到）**：复权行情取不到时，改用东财**净值接口** `fund_etf_fund_info_em`（同域不同端点，实测可用，返回单位净值 / 累计净值），用**累计净值**的收益率近似总收益；也可以直接用指数收益率作板块收益代理。这样贝塔与相关性不必等复权行情恢复才能算。

**8 个板块指数与基准（2026-10-10 实测，全部可定位）**：

| 板块 | ETF | 指数代码 | 指数名称 | 口径 | 起点 | ETF↔指数相关性 |
| --- | --- | --- | --- | --- | --- | --- |
| 银行 | 512800 | `399986` | 中证银行 | csindex | 2005-01-04 | 0.720 ※ |

| 家电 | 159996 | `930697` | 中证全指家用电器 | csindex | 2005-01-04 | 0.986 |
| 光伏 | 159857 | `931151` | 中证光伏产业 | csindex | 2012-12-31 | 0.993 |
| 稀土 | 159713 | `930632` | 中证稀土产业 | csindex | 2012-01-04 | 0.900 |
| 机器人 | 562500 | **`H30590`** | 中证机器人指数 | csindex | **2011-01-04** | **0.986** |
| 光模块（通信设备） | 515880 | `931160` | 中证全指通信设备 | csindex | 2018-12-28 | 0.745 ※ |
| 电池 | 159755 | `980032` | 国证新能源车电池 | **sina** | 2013-01-04 | 0.992 |
| 基准 | — | `sh000300` | 沪深300 | sina | 2002-01-04 | — |

※ **低相关的原因与处理**：银行 0.720、通信 0.745 偏低，是**ETF 侧用了未复权价**（银行 ETF 分红多；通信 ETF 疑似有份额折算，会产生跳空缺口）。两个指数代码本身经公开资料核对无误。→ **需用复权价复算**；复权取不到时，改以指数收益率作为板块的收益代理（指数已是价格/全收益口径，不受分红影响）。

**相关性反查的作用**：把「ETF ↔ 指数」的配对用日收益相关性验证，比猜代码可靠。机器人指数即由此确认——候选 `932036` 相关性 **−0.17** 被排除，`H30590` **0.986** 命中。

**贝塔系数**：`beta = cov(r_标的, r_基准) / var(r_基准)`。**2026-10-11 定：只认中证500 作基准，且只有 ETF 出贝塔，IC/IF 不出。** 窗口给「全历史」与「近 250 日」两列；价格口径优先净值/累计净值（见上条替代口径）。初步实测（未复权行情口径，仅形态参考）：银行 0.27、家电 0.70、券商 0.94、光伏 1.10、稀土 1.15、机器人 1.10、通信 1.19、电池 1.10。

## 三、模块设计

### 3.1 工具清单（Agent 可调用）

工具用 **TypeBox** 声明签名，与 Pi 内置工具同风格（参考 `packages/coding-agent/src/core/tools/write.ts`）。

| 工具 | 入参（要点） | 出参（要点） | 后端 |
| --- | --- | --- | --- |
| `get_holdings` | 无 | 持仓列表 + 偏好 | 本地 `data/holdings.json` |
| `save_holding` | 标的 / 类型 / 数量 / 成本价 / 开仓日 / 备注 | 更新后的持仓 | 同上 |
| `save_preferences` | 偏好字段 | 更新后的偏好 | `data/preferences.json` |
| `baseline_deviation` | 标的列表（默认全部）/ 窗口 | 每标的：当前值 / **ETF 基线**偏离% / **指数基线**偏离% / 斜率 / R² / 贝塔（基准＝中证500，仅 ETF 出） | Python 适配层 |
| `fetch_futures_daily` | 品种（IC/IF）/ 区间 | 落库结果 + 行数 | `icbt/fetch.py` |
| `fetch_etf_daily` | ETF 代码列表 / 区间 | 落库结果 + 行数 | 适配层 |
| `data_health` | 可选：日期 | 四维自检结论 + 明细 | `icbt/ops/checks.py:run_all` |
| `run_backtest` | 策略配置（JSON）/ 区间 / 标的 | 绩效卡 + 资金曲线数据 + run_id | `icbt/runner.py:run` |
| `sweep_params` | 基准配置 + 扫描网格 | 结果汇总表 | `icbt/runner.py:sweep` |
| `compare_holdings` | 区间 / 对照标的 A、B | 两条净值 + 收益差（反事实回测） | 适配层（`run_backtest` 两次） |
| `fetch_article_maobidao` | 无（取最新） | 标题 / 日期 / 正文 / 链接；已存在则返回已存档 | 浏览器登录态 |
| `fetch_news` | 日期 | 要闻列表（含来源、时间） | 东财 / 同花顺 |
| `render_daily_report` | 四块数据 | 生成的 HTML 路径 | 渲染层 |

工具定义要点：

- 有结构化数据返回的工具声明 `outputSchema` 并返回 `structuredContent`；
- 失败**抛错**，不要用返回值表达错误（Pi 的约定）；
- 会互相影响状态的工具（如 `save_holding`）标 `executionMode: "sequential"`。

### 3.2 Python 适配层（`assistant/py/`）

一个薄 CLI，把 `icbt` 的能力变成 JSON 进程接口。**不新增业务逻辑，只做参数转换与序列化。**

```bash
python -m assistant.py.bridge backtest --config run.json   # → JSON stdout
python -m assistant.py.bridge sweep    --config run.json --grid grid.json
python -m assistant.py.bridge health
python -m assistant.py.bridge baseline --codes 512800,159713,...
python -m assistant.py.bridge update   --variety IC,IF
```

映射关系（无需改 `icbt`）：

| bridge 子命令 | 调用的既有实现 |
| --- | --- |
| `backtest` | `icbt/runner.py:222` `run(config)` → `RunResult.to_dict()` |
| `sweep` | `icbt/runner.py:323` `sweep(base, grid)` |
| `health` | `icbt/ops/checks.py:445` `run_all` |
| `baseline` | `icbt/settings.py:50` `baseline_point` / `baseline_deviation` 的口径，扩展到多标的 |
| `update` | `icbt/fetch.py` 与 `scripts/update_data.py:42`（退出码 0/1/2 语义保留） |

注意事项：

- `icbt` 的 `Market` 是模块级单例（`load_market()`），CLI 每次调用都是新进程，天然规避状态串味；
- 输出统一 `{"ok": true, "data": ...}` / `{"ok": false, "error": {...}}`，Node 侧只解析 JSON；
- 大结果（净值序列）按需截断或落文件，避免 stdout 过大。

### 3.3 H5 与后端接口

一期只做最小可用：静态 HTML + 一个流式接口。

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/chat` | POST（SSE 流式） | 入参消息文本；出参增量文本 + 工具调用事件 |
| `/api/holdings` | GET / POST | 读 / 写持仓 |
| `/api/preferences` | GET / POST | 读 / 写偏好 |
| `/api/reports/latest` | GET | 返回最新日报 HTML 路径，前端跳转或内联 |
| `/api/backtest` | POST | 直接触发一次回测（等价于 `run_backtest` 工具） |

前端沿用附录 B 设计语言，纯静态 + 原生 fetch/EventSource，不引入构建链。

### 3.4 报告渲染（白色系）

- 日报与复盘报告都是**自包含单文件 HTML**（可离线双击打开），沿用 `icbt/report.py` 的思路：数据内联、图表用轻量 canvas 手绘，不引入图表库；
- 复用 Pi 的 `light` 主题色板思路与本项目设计 token（`#f5f6f8` / 白卡 12px / `#2f6fd6` / `#e0415b`）；
- 日报四块：(a) 文章原文（原样，含发布日期与抓取时间）(b) 要闻 + 申万一级异动 (c) 机会与关注（带来源/置信度）(d) 基线偏离表 + 小图；
- 复盘报告：绩效对比 + 反事实结论，**可导入飞书**（表格用内联样式、无外部依赖）。

### 3.5 调度

Pi **没有内置定时能力**，用 macOS `launchd`：

| 任务 | 时点 | 说明 |
| --- | --- | --- |
| 日报生成 | 每日 09:00 | 生成 HTML；按配置决定是否推送 |
| 猫笔刀抓取 | 每日 11:30 | 抓最新一篇、存档、判重 |
| 数据更新 | 交易日 15:40 / 17:30 | 沿用 `icbt` 既有节奏（`ic_backtest/configs/launchd/com.changsir.icbt.update.plist` 可照抄） |
| 指数与行业更新 | 每日 00:20 | 同上 |

`launchd` 直接调 `python -m assistant.py.bridge update` 或一个 Node 一次性脚本，不依赖常驻进程。

## 四、关键实现约束

| 约束 | 说明 |
| --- | --- |
| 数据源回退 | 东财行情接口会间歇性拒连（实测），任何取数都必须多源回退：ETF/个股 → 东财 → 新浪；指数 → 中证指数公司 → 新浪 → 东财；国证指数只有新浪口径。取数失败要可见、可重试，不静默 |
| 价格口径 | 收益 / 贝塔计算优先用**净值或累计净值**口径；复权行情接口被网络层重置（见 2.3），退到未复权时必须在日报标注 |
| 无前视 | 基线参数冻结、不随新数据重拟合；日报数据一律取上一交易日收盘 |
| 数据口径 | 「10 年历史」不是整体可达：期指 IC 2015+/IF 2010+、宽基指数 2002/2005+、申万一级多数 ≥12.6 年，但 **8 只 ETF 本体只有 4.8–10.2 年**。长周期板块回测用申万一级或中证行业指数，ETF 本体只做基线与净值。取数须处理 csindex 首行坑（见 2.3） |
| 时序口径 | 09:00 生成 ⇒ (b)(c)(d) 为「上一交易日收盘 + 隔夜」；(a) 为前一交易日 11:30 抓到的最新一篇 |
| 结果可复现 | 回测沿用 `icbt` 的 `run_id = hash(配置 + 数据版本 + 代码版本)`，缓存命中直接返回 |
| 失败不静默 | 任一区块抓取/计算失败，必须在日报与对话中显式标注 |
| 密钥不入库 | 走环境变量或 `auth.json`；`.gitignore` 排除 `data/`、`auth.json`、`*.env` |

### 9.3 三个外部源的实测接口（原 2.3 的补充）

| 源 | 接口 | 实测 |
| --- | --- | --- |
| 同花顺快讯 | `news.10jqka.com.cn/tapp/news/push/stock/?page=N&pagesize=200` | 页面是 JS 渲染，但**这个 JSON 接口免鉴权**；字段 `id/title/digest/ctime/tags/stock`。⚠️ `tags` 是 **list[dict]** 不是 list[str] |
| 东财研报 | `reportapi.eastmoney.com/report/list?qType=0(个股)/1(行业)` | 免鉴权，字段含 `infoCode/title/orgSName/indvInduName/emRatingName/publishDate` |
| 猫笔刀文章（主） | `wechat2rss.xlab.app/feed/33d986064f59be5263de2ca822fb3e0bdd59eb81.xml` | **全文在 `content:encoded` 元素**（`description` 是空的）。feed id 是第三方分配，**无法从公众号 `__biz` 推导** |
| 猫笔刀文章（备） | `maobidao.net/index.php?rest_route=/wp/v2/posts&categories=1` | WordPress REST API，`content.rendered` 是全文；**支持 `per_page=100&page=N` 翻页**（实测 236 篇 / 3 页）；正文内嵌带 `chksm` 的 mp 原文链 |

**文章链接形式的坑**：`/s?__biz=…&sn=…` 长链**没有 `chksm` 参数会被反爬**（返回 17KB 验证页），而 `/s/<token>` 短链能直连拿到正文（3.4MB）。**同一个链接不要连发两次请求**，第二次会被限流返回验证页。

### 9.4 对前文口径的修正（重要）

| 原写法 | 修正为 | 依据 |
| --- | --- | --- |
| 文章「11:30 抓取、按日期+标题判重」 | **RSS 主 + 备份站备；按 `(account, title)` 去重** | 备份站的 `date` 是"备份发布日"，比实际发布日**晚约一天**，用日期去重会同一篇存两份（255 vs 235） |
| 文章只有最新一篇 | **可拿全部历史**：`article --all`（RSS ~20 篇）+ `backfill --pages 3`（备份站 236 篇）→ 已入库 **235 篇 / 2025-03-07→2026-10-11 / 全带正文** | 单篇文章链接只能拿到那一篇；历史必须走清单类接口 |
| 资讯"抓上一交易日要闻" | **快讯与研报全量入库，保留 90 天窗口，日报只展示与 8 板块/持仓相关的** | 他要求"全量入库、日报只显示相关"，且"最多 3 个月、可短不可长" |
| ETF 贝塔用 ETF 收益 | **用其跟踪指数的日频收益** | ETF 只取稀疏点（年末+最新），没有日频序列，算不了贝塔 |
| 调度用 launchd | **改用 ZCode 内置定时任务** | 见 9.5 |

### 9.5 定时：launchd 不可用（macOS TCC 保护桌面）

launchd 三个任务已成功安装并注册，但**执行时被拒**：

```
python: can't open file 'news.py': [Errno 1] Operation not permitted
```

**根因是 macOS TCC**：`~/Desktop` 属受保护目录，后台任务默认无权读取（是 `Operation not permitted` 而非文件不存在）。项目放在桌面，launchd 就注定跑不了。

**采用的方案**：改用 **ZCode 内置定时任务**（ZCode 应用有桌面权限，绕开 TCC）——一个任务串三步：
`每日09:00 投资助手例行（数据+文章+晨报）`。三步取同一份快照，且符合"09:00 的日报展示前一晚那篇"的口径。

三个 plist 保留在 `assistant/launchd/` 作备用，**已从 `~/Library/LaunchAgents` 卸载**（避免每晚报错）。若要用系统级定时，需**把项目移出桌面**或给 `/bin/zsh` 完全磁盘访问权限。

（顺带：plist 的 `ProgramArguments` 是数组，**只能放 `<string>`**，误放 `<key>` 会让 `launchctl bootstrap` 报 "Input/output error"。）
