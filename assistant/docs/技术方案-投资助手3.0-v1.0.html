一、总体架构

1.1 分层

             ┌──────────────┐
   H5 前端 ──▶│  Node 服务   │  ← Pi agent 底座（对话 / 工具循环 / 会话 / 压缩）
  (assistant/ │  (assistant/ │
   h5)        │   src)       │
             └──────┬───────┘
                    │ 工具层（TypeBox 签名）
     ┌──────────────┼──────────────────────┐
     ▼              ▼                      ▼
 Python 适配层   资讯 / 文章抓取        报告渲染
 (assistant/py)  (浏览器登录态 / HTTP)   (HTML, 白色系)
     │
     ▼
 icbt 内核（只读复用，不改）
 行情 / 面板 / 规则引擎 / 回测引擎 / 数据自检

原则：Node 侧只做对话与编排，Python 侧只做数据与计算，渲染与展示分离。

1.2 为什么不改 icbt

icbt 已跑通并验证过口径（无前视约束、四维数据自检、可复现 run_id）。助手只需要「调用」它：

  • 只读复用 icbt/runner.py、icbt/fetch.py、icbt/data.py、icbt/ops/checks.py、icbt/rules/*；
  • 在 assistant/py/ 加一层薄 CLI，把已有函数包成「吃 JSON 吐 JSON」的进程接口；
  • icbt 自身升级不影响助手，助手出问题也不污染回测平台。

    • 1.3 与 Pi 上游的边界

    目录归属说明
    packages/Pi 上游一个字节都不改，保持可跟上游 diff / 升级
    assistant/本项目全部自有代码、配置、数据、文档

    扩展 Pi 一律走它提供的扩展点（SDK 注入 / extension / 自定义工具），不改 packages/。

    二、技术选型

    2.1 Agent 运行时

    用 @earendil-works/pi-coding-agent 的 SDK（而非从零用 pi-agent-core），因为需要会话管理、上下文压缩、资源加载与 hooks：

    import { createAgentSession, DefaultResourceLoader, SessionManager } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession({
  resourceLoader: new DefaultResourceLoader({
    systemPromptOverride: INVESTMENT_SYSTEM_PROMPT,   // 投资助手人格与规则
  }),
  customTools: investmentTools,          // 见 3.1
  model,                                 // 见 2.2
});

    保留 Pi 自带的 bash / read / write：本助手天然需要读写本地文件、以子进程调用 Python 适配层，这三个工具正好承载。

    备选（如后期要换成独立服务进程）：用 pi --mode rpc 以 JSONL 驱动子进程（docs/rpc.md 里有 Python 客户端示例），或 RpcClient。

    2.2 模型与 Provider

    DeepSeek 是 Pi 的内置 provider，无需自己写适配：

    项值
    provider iddeepseek
    baseUrlhttps://api.deepseek.com
    apiopenai-completions
    密钥来源环境变量 DEEPSEEK_API_KEY，或 <agent-dir>/auth.json

    零代码的替代方式是 <agent-dir>/models.json 里配一个 OpenAI 兼容块。密钥只走环境变量或 auth.json，不进仓库、不写进 watchlist.yaml。

    模型注册（2026-10-11 实测通过，结论与原假设不同）：用你的 key 实测了你的 DeepSeek 账号，结果：

  • 账号下实际可用的 id 只有两个：deepseek-flash（显示名 DeepSeek-V4.1-Flash，API 明确返回 input_modalities: ['text','image']）与 deepseek-v4-pro（纯文本）。
  • 主模型 deepseek-flash 本身就支持图片 —— 已用日报截图实测，它能准确读出「贝塔」列表头与全部 10 个数值（0.06、—、0.59、1.20、0.91、1.19、1.19、1.18、1.23、1.31）以及 +19.0% 的偏离值。
  • → 不需要单独注册视觉模型，复盘读图也不需要切模型。 原先设想的 deepseek-v4-flash-vision-exp 在你这套账号下并不存在（那是 Pi catalog 里的实验性条目）。
  • 注册方式（零代码）：在 <agent-dir>/models.json 声明 provider 与模型，密钥用 $DEEPSEEK_API_KEY 环境插值，不落盘明文。本项目放在 assistant/pi-agent/models.json，用 PI_CODING_AGENT_DIR 指向该目录。
  • 实测命令：PI_CODING_AGENT_DIR=…/assistant/pi-agent DEEPSEEK_API_KEY=… ./pi-test.sh --model deepseek/deepseek-flash --print "…" —— 成功跑通，并完成了一次真实的 bash 工具调用（返回 pi-tool-ok）。

    取数坑（实现时必须处理）：

  • stock_zh_index_hist_csindex 返回的首行是 base-date 合成行（如 2004-01-01，收盘值与次行相同），直接 min(date) 会把起点误判成 2004 年——必须丢弃首行再用。
  • 申万一级有 3 个行业不足 10 年，做板块长历史回测时要么剔除，要么改用中证对应行业指数。
  • 国证指数（980032 新能源车电池）不在中证口径，csindex 接口取不到，需另找取数口径或改用申万「电力设备」。
  • index_hist_sw 的 symbol 要用裸代码（801010），传 sw_index_first_info() 返回的 801010.SI 会报列名错误。
  • 国证指数（980032 新能源车电池）不在中证口径：csindex / 东财都取不到，只有新浪 stock_zh_index_daily(symbol="sz980032") 可取。
  • 东财行情接口（fund_etf_hist_em、stock_zh_index_spot_em）被网络层立即重置（0.1s 就断开——不是限频，限频会返回状态码；同日实测上午可用、下午起持续被拒）。→ 必须多源回退。
  • 复权价的替代口径（2026-10-11 找到）：复权行情取不到时，改用东财净值接口 fund_etf_fund_info_em（同域不同端点，实测可用，返回单位净值 / 累计净值），用累计净值的收益率近似总收益；也可以直接用指数收益率作板块收益代理。这样贝塔与相关性不必等复权行情恢复才能算。

    • 3.2 Python 适配层（assistant/py/）

    一个薄 CLI，把 icbt 的能力变成 JSON 进程接口。不新增业务逻辑，只做参数转换与序列化。

    python -m assistant.py.bridge backtest --config run.json   # → JSON stdout
python -m assistant.py.bridge sweep    --config run.json --grid grid.json
python -m assistant.py.bridge health
python -m assistant.py.bridge baseline --codes 512800,159713,...
python -m assistant.py.bridge update   --variety IC,IF

    映射关系（无需改 icbt）：

    bridge 子命令调用的既有实现
    backtesticbt/runner.py:222 run(config) → RunResult.to_dict()
    sweepicbt/runner.py:323 sweep(base, grid)
    healthicbt/ops/checks.py:445 run_all
    baselineicbt/settings.py:50 baseline_point / baseline_deviation 的口径，扩展到多标的
    updateicbt/fetch.py 与 scripts/update_data.py:42（退出码 0/1/2 语义保留）

    注意事项：

  • icbt 的 Market 是模块级单例（load_market()），CLI 每次调用都是新进程，天然规避状态串味；
  • 输出统一 {"ok": true, "data": ...} / {"ok": false, "error": {...}}，Node 侧只解析 JSON；
  • 大结果（净值序列）按需截断或落文件，避免 stdout 过大。

    • 3.3 H5 与后端接口

    一期只做最小可用：静态 HTML + 一个流式接口。

    接口方法说明
    /api/chatPOST（SSE 流式）入参消息文本；出参增量文本 + 工具调用事件
    /api/holdingsGET / POST读 / 写持仓
    /api/preferencesGET / POST读 / 写偏好
    /api/reports/latestGET返回最新日报 HTML 路径，前端跳转或内联
    /api/backtestPOST直接触发一次回测（等价于 run_backtest 工具）

    前端沿用附录 B 设计语言，纯静态 + 原生 fetch/EventSource，不引入构建链。

    3.4 报告渲染（白色系）

  • 日报与复盘报告都是自包含单文件 HTML（可离线双击打开），沿用 icbt/report.py 的思路：数据内联、图表用轻量 canvas 手绘，不引入图表库；
  • 复用 Pi 的 light 主题色板思路与本项目设计 token（#f5f6f8 / 白卡 12px / #2f6fd6 / #e0415b）；
  • 日报四块：(a) 文章原文（原样，含发布日期与抓取时间）(b) 要闻 + 申万一级异动 (c) 机会与关注（带来源/置信度）(d) 基线偏离表 + 小图；
  • 复盘报告：绩效对比 + 反事实结论，可导入飞书（表格用内联样式、无外部依赖）。

    • 3.5 调度

    Pi 没有内置定时能力，用 macOS launchd：

    任务时点说明
    日报生成每日 09:00生成 HTML；按配置决定是否推送
    猫笔刀抓取每日 11:30抓最新一篇、存档、判重
    数据更新交易日 15:40 / 17:30沿用 icbt 既有节奏（ic_backtest/configs/launchd/com.changsir.icbt.update.plist 可照抄）
    指数与行业更新每日 00:20同上

    launchd 直接调 python -m assistant.py.bridge update 或一个 Node 一次性脚本，不依赖常驻进程。

    四、关键实现约束

    约束说明
    数据源回退东财行情接口会间歇性拒连（实测），任何取数都必须多源回退：ETF/个股 → 东财 → 新浪；指数 → 中证指数公司 → 新浪 → 东财；国证指数只有新浪口径。取数失败要可见、可重试，不静默
    价格口径收益 / 贝塔计算优先用净值或累计净值口径；复权行情接口被网络层重置（见 2.3），退到未复权时必须在日报标注
    无前视基线参数冻结、不随新数据重拟合；日报数据一律取上一交易日收盘
    数据口径「10 年历史」不是整体可达：期指 IC 2015+/IF 2010+、宽基指数 2002/2005+、申万一级多数 ≥12.6 年，但 8 只 ETF 本体只有 4.8–10.2 年。长周期板块回测用申万一级或中证行业指数，ETF 本体只做基线与净值。取数须处理 csindex 首行坑（见 2.3）
    时序口径09:00 生成 ⇒ (b)(c)(d) 为「上一交易日收盘 + 隔夜」；(a) 为前一交易日 11:30 抓到的最新一篇
    结果可复现回测沿用 icbt 的 run_id = hash(配置 + 数据版本 + 代码版本)，缓存命中直接返回
    失败不静默任一区块抓取/计算失败，必须在日报与对话中显式标注
    密钥不入库走环境变量或 auth.json；.gitignore 排除 data/、auth.json、*.env
    只读外部对外只 GET；公众号仅用登录态读公开文章

    源接口实测

    9.4 对前文口径的修正（重要）

    原写法修正为依据
    文章「11:30 抓取、按日期+标题判重」RSS 主 + 备份站备；按 (account, title) 去重备份站的 date 是"备份发布日"，比实际发布日晚约一天，用日期去重会同一篇存两份（255 vs 235）
    文章只有最新一篇可拿全部历史：article --all（RSS ~20 篇）+ backfill --pages 3（备份站 236 篇）→ 已入库 235 篇 / 2025-03-07→2026-10-11 / 全带正文单篇文章链接只能拿到那一篇；历史必须走清单类接口
    资讯"抓上一交易日要闻"快讯与研报全量入库，保留 90 天窗口，日报只展示与 8 板块/持仓相关的他要求"全量入库、日报只显示相关"，且"最多 3 个月、可短不可长"

    9.5 定时：launchd 不可用（macOS TCC 保护桌面）

    launchd 三个任务已成功安装并注册，但执行时被拒：

    python: can't open file 'news.py': [Errno 1] Operation not permitted

    根因是 macOS TCC：~/Desktop 属受保护目录，后台任务默认无权读取（是 Operation not permitted 而非文件不存在）。项目放在桌面，launchd 就注定跑不了。

    采用的方案：改用 ZCode 内置定时任务（ZCode 应用有桌面权限，绕开 TCC）——一个任务串三步：

    每日09:00 投资助手例行（数据+文章+晨报）。三步取同一份快照，且符合"09:00 的日报展示前一晚那篇"的口径。

    三个 plist 保留在 assistant/launchd/ 作备用，已从 ~/Library/LaunchAgents 卸载（避免每晚报错）。若要用系统级定时，需把项目移出桌面或给 /bin/zsh 完全磁盘访问权限。

    （顺带：plist 的 ProgramArguments 是数组，只能放 <string>，误放 <key> 会让 launchctl bootstrap 报 "Input/output error"。）
